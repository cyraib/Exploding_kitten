Open **http://127.0.0.1:4177/app/editor/index.html**, or click **EDITOR** in the game toolbar. Start the normal server with `npm start` or the existing game shortcut. No packages or external services are required.

## Working in the dashboard

- **Overview:** counts, theme variables, undo, draft recovery, discard and default configuration. Edits preview immediately; Save project writes the configuration to disk. Export/import exchanges the entire validated JSON configuration.
- **Interface:** 26 mapped components; editable selectors, images/backgrounds, text labels, CSS properties, hover/active/disabled styles and mobile/tablet/desktop overrides. Use the property picker for individual values, or the JSON fields for several values. Leaf text labels are changed without deleting component controls. Arbitrary visual styles can obscure controls; discard/reset or undo recovers them.
- **Animations:** all 10 JavaScript motion primitives, 9 CSS keyframe animations and 9 CSS transitions: 28 entries. Each entry includes trigger, component, sound where applicable, original keyframes or measured-path reference, source and function. Common tuning uses duration, delay, speed, easing, distance, scale, rotation, opacity, intensity and enabled state. Play/replay/pause/slow motion/resume/reset exercise the preview; restore defaults resets the selected configuration. JavaScript draw, shuffle, flight, stamp, danger, Defuse, turn and confetti previews call actual game presentation functions. CSS previews apply actual stylesheet keyframes to a sample. Transitions use an illustrative sample; inspect/hover the live component to see its real state transition.
- **Feature map:** 22 mechanics and systems, including pairs/triples, saves, public logs, bots and victory. Related components, animations, sounds, dependencies and incoming references are clickable. Source buttons fetch the actual local file, show line numbers and highlight the mapped symbol. Engine mechanics are never duplicated in the dashboard.
- **Entities:** create, duplicate, rename, delete or disable data entries. Bot templates control names, avatars, presentation and optional difficulty (`inherit`, `casual`, `clever`); player templates supply default setup names and human-seat styles. Effects/notifications/game objects are static presentation objects. A `font` entity loads its local font asset with the entity name as its CSS font-family; set that family in Interface. A `music` entity plays its audio asset in a loop while game sound is enabled; `behavior.volume` accepts 0–0.2. Sounds are editable synthesized cues or uploaded audio replacements; duplicate a sound to create another cue, then assign it to cards.
- **Cards & decks:** create supported-effect variants, duplicate/delete cards, edit names, IDs, artwork, icons, descriptions, detail text, colors, default quantities, UI faces/icons/text, effects, animation and sound. Deck membership has independent quantities. Duplicate a deck to create another, change its inventory and start a sandbox with it. New tables use the configured inventory; existing saves retain their inventory/catalog snapshot.
- **Assets:** all 265 original image files are searchable, plus newly uploaded images/audio/fonts. View previews and active configuration reference chains; replace every configuration reference to a selected path at once. Images can replace faces/icons/backgrounds; audio can replace cues/music; fonts load through font entities. Uploads have unique names under `app/config/uploads/`, never overwrite `Assets/`, and are limited to 8 MB.
- **Visual inspector:** enable Inspect element, then click in the game preview. The component’s ID, current image or CSS background, rectangle, computed styles, active animations, mapped handler/feature and actual source are displayed. Inspection consumes the click without performing the game action.
- **Search:** searches all configuration records, their implementation references and available assets. It returns cards, features, motion and source/function mappings together. This is an architecture catalog search, not a repository full-text search.
- **Debug sandbox:** create 2–5-seat tables; move a specific card into/out of a hand; force a Kitten draw/Defuse/Attack/Nope/Future; change the current seat; reorder the entire deck; eliminate a seat; reset with a new bot count; execute a real bot decision; force a winner; submit ordinary engine commands. Card moves preserve inventory and hazards stay out of hands. Sandbox scenarios stop automatic bot/reaction timers so they remain inspectable, while ordinary gameplay keeps the full three-second response window. Finish a reaction with PASS commands for the displayed responder; CLOSE_FUTURE closes a peek; INSERT supplies a legal secret position.

## Architecture and persistence

`app/config/project.json` is the editable structured configuration. `app/config/defaults.json` is the reset baseline. Schema validation is in `app/config/validation.js`. The game consumes presentation settings through `app/config/runtime.js`, uses `app/catalog.js` for card definitions and `app/ui-config.js` for deck/mode listings. `app/engine.js` accepts optional inventory/catalog snapshots and maps variants to existing effects. `app/bots.js` evaluates those effects through its restricted observation.

The separate editor lives in `app/editor/`. Only `/?editor=1` dynamically imports its bridge. Normal play does not load the dashboard or bridge; removing `app/editor/` leaves the game operational (the optional toolbar link then has no destination). Without optional configuration the game uses its original card/motion defaults.

Preview preferences/saves use `ek-editor-sandbox-*` keys; normal saves use the existing `ek-original-*` keys. A sandbox can display every seat's hand and deck for debugging. Normal bot observations and normal player UI continue to protect hidden information.

Save writes only `app/config/project.json`, first saves a backup under `.codex/editor-backups/`, replaces the file via a temporary write, and checks the exact prior text to reject concurrent-edit conflicts. The loopback-only server restricts mutations to same-origin JSON and limits upload types/body sizes. Local source viewing is restricted to game JS/CSS and `index.html`; private project logs are not served. Original downloaded files and surviving source URLs remain untouched.

## Boundaries

The engine implements Original Edition effects and matching combos. New cards can reuse those effects; a novel expansion mechanic needs an engine implementation and registration. Rescue, Nope and Kitten IDs remain canonical. Enabled decks must supply at least six Defuses, four Kittens and 35 ordinary cards so all supported seat counts can start. Supported targeting/play conditions follow their effect and cannot be changed into an unsupported rule. There is no HP mechanic, online play, rule scripting, arbitrary JavaScript execution or generic DOM event-listener introspection. Inspector handler information comes from the maintained code map.

Deleting a built-in animation entry removes its override; use Enabled=false to suppress it. Primitive geometric controls affect common transforms, with measured flight endpoints retained; custom keyframes provide detailed geometry. CSS distance/scale/intensity changes are expressed through their editable CSS keyframes. CSS motion previews use samples rather than simulating engine state. New bot counts recreate the sandbox rather than adding seats midway through a match. Existing browser names/settings take precedence over the new player-template default. Source mappings should be updated alongside future code changes.
